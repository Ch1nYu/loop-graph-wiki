# 退回邊與檢查前移：大圈少轉，小圈快轉

> 一句話：好的 Graph 不是沒有錯誤，而是錯誤在離源頭最近的地方被發現、被修掉。

## 兩種迴圈：小圈與大圈

課程把 Graph 裡的迴圈分成兩種（[[sources/week10-lecture]] §3.3）：

- **小圈（Local Loop）**：在單一節點內部或相鄰節點之間快速修正。例如逐頁稿節點內部跑「寫一頁 → 檢查出處 → 修改」，最多 2 輪；渲染節點跑「產生 HTML → 截圖 → 修版面」，最多 3 輪。
- **大圈（Global Fallback）**：從最後一關一路退回最前面的起點。例如簡報做到第 12 頁才發現「整個主題選錯」或「來源少了關鍵論文」，只好退回檢索重做。

黃金原則是：**大圈很少轉，小圈轉得很快**。大圈每次都很貴，應該極少發生；小圈在附近快速修，成本低、定位準（[[sources/week10-lecture]] §3.3）。

## 精準退回的四個例子

課程給了四個很具體的退回規則（[[sources/week10-lecture]] §5.3(3)）：

| 錯誤 | 錯誤的修法 | 正確的退回 |
|---|---|---|
| 第 6 頁結論講反 | 整份簡報重生成 | 只退回第 6 頁的逐頁稿，其他 12 頁不動 |
| 證據卡一開始就抽錯 | 叫逐頁稿節點「自己想辦法」 | 退回證據卡節點，重抽那一篇 |
| 第 5 頁字太多溢出 | 把字縮到螞蟻大小硬塞 | 退回逐頁稿，刪減文字 |
| 大綱缺一個重要子題 | 等簡報做完才發現 | 在大綱關卡退回檢索，補資料 |

這四個例子的共同點是：**退回的目標是「錯誤的來源」，不是「最後的成品」**。如果錯誤來自證據卡，修逐頁稿只是治標；如果錯誤來自大綱，修版面只是遮蓋。

## 檢查前移：為什麼要在大綱就抓錯

課程的核心診斷是：「錯誤必須在離源頭最近的地方被抓到。如果你的 Graph 常常在轉大圈，代表你的檢查關卡設得太後面了。」（[[sources/week10-lecture]] §3.3）

例如：

- 如果等到 HTML 做完才發現「少讀了兩篇論文」，就要退回檢索、重抽卡、重寫大綱、重寫逐頁稿、重渲染——這是大圈。
- 如果在大綱階段就檢查覆蓋率，發現少兩篇，只要退回檢索補卡，再修大綱——這是小圈。

這就是「檢查前移」：把檢查從成品端移到決策端。越早發現，退回成本越低。

## 退回邊怎麼設計

設計退回邊時，問三個問題：

1. **這個錯誤的源頭是哪個節點？**（檢索、證據卡、大綱、逐頁稿、渲染）
2. **退回後要重跑哪些節點？**（只重跑受影響的，不要整份重跑）
3. **退回的上限是幾次？**（超過就停止，請人類介入）

以本專案為例：

```text
<G1 覆蓋率> ──不足──▶ 停止
<G2 大綱>   ──缺子題──▶ 退回 N1 補檢索
<G3 忠實度> ──某頁錯──▶ 退回該頁 N4
<G4 版面>   ──溢出──▶ 退回該頁 N4 刪字
<G5 獨立審查> ──覆蓋不足──▶ 退回 N2 補卡 → N4 補頁
```

每一條退回邊都指向「錯誤的源頭」，而且有次數上限。

## 退回的成本意識

退回不是免費的：每次退回都要重讀來源、重寫、重檢查，消耗 token 與時間。因此：

- 小圈的上限要小（2–3 輪），避免在同一個問題上打轉。
- 大圈的上限要更小（1 次），因為大圈通常代表規格或資料有問題，不是 AI 不夠努力。
- 如果同一個錯誤改了 3 次還沒好，應該停下來檢查「規格是不是寫錯了」，而不是繼續重試（[[sources/week10-lecture]] §3.2）。

Harness 的 Detector 也提醒：偵測卡住要用「明確缺乏進展」當條件，並且先寫誤報測試；被忽略的警報等於沒有警報（[[sources/agentic-harness-kimi-k3]] §BUILD 09）。

## 反模式

| 反模式 | 問題 | 替代做法 |
|---|---|---|
| 所有錯誤都退回起點 | 大圈一直轉，成本爆炸 | 只退回錯誤源頭 |
| 用縮字/改 CSS 解決內容太多 | 治標不治本，讀者還是看不懂 | 退回逐頁稿刪減內容 |
| 沒有退回上限 | 同一個錯誤無限重試 | 設 2–3 輪上限，超過就停 |
| 檢查只放在最後 | 錯誤太晚發現 | 把檢查前移到證據卡、大綱、逐頁稿 |

## 教學用法

讓學生畫一條「簡報製作流程」，然後問：「如果第 6 頁的數字錯了，你要退回哪裡？」大部分學生會說「退回第 6 頁」；追問「如果這個數字是從證據卡就抄錯的呢？」學生就會發現需要區分「逐頁稿錯」與「證據卡錯」。這個練習可以很好地帶出「退回源頭」的概念。

## 檢查清單

- [ ] 每個檢查關卡是否有明確的退回目標？
- [ ] 退回目標是否指向錯誤的源頭，而不是最後的成品？
- [ ] 每個退回邊是否有次數上限？
- [ ] 是否把檢查前移到決策端（大綱、證據卡）？
- [ ] 是否避免用版面技巧掩蓋內容問題？
